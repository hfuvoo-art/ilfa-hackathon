# AGENTS.md — правила для ИИ-ассистентов (читать ПЕРВЫМ)

Этот файл читает любой ИИ-ассистент (Claude Code, Cursor, Codex, Copilot и др.) перед работой в репозитории. `CLAUDE.md` просто подключает этот файл.

## 1. Проект в двух словах

Хакатон, кейс сети стоматологических клиник «Ильфа»: «Маркетинг, который помнит каждого пациента».
Есть 8 652 файла `.xls`, каждый — один визит пациента. Нужно:
1. собрать их в единую чистую базу;
2. сделать аналитику: сегменты пациентов, LTV, прибыльные услуги, сезонность;
3. генерировать персональные предложения пациентам (тон «забота», а не реклама);
4. показать работающий веб-прототип;
5. защитить проект: презентация с экономикой эффекта и дорожной картой.

Критерии жюри: глубина и наглядность аналитики; расчёт эффективности; архитектура решения; практическая ценность и убедительность презентации.

## 2. Карта репозитория и владельцы

| Папка | Роль | Что внутри |
|---|---|---|
| `etl/` | Data-инженер | Парсер xls → база, очистка, справочник услуг |
| `analytics/` | Аналитик | Сегменты, LTV, сезонность, графики, дашборд |
| `offers/` | ML/LLM-разработчик | Триггеры (поводы), признаки из комментариев, генерация текстов |
| `app/` | Fullstack-разработчик | API (FastAPI), интерфейс (Streamlit), Docker |
| `docs/` | Руководитель | Экономика, дорожная карта, презентация, материалы защиты |
| `shared/` | Все (только по согласованию) | `DATA_CONTRACT.md` — единая схема таблиц |
| `data/` | Локально у каждого | Сырые и обработанные данные. В git НЕ попадают |

План конкретной роли лежит в `<папка>/AGENTS.md`. Прочитай его, когда пользователь назвал свою роль.

## 3. Жёсткие правила (нарушать нельзя)

1. **Работай только в папке роли пользователя.** Если пользователь сказал «я аналитик», ты создаёшь и меняешь файлы только в `analytics/`. Чужие папки можно ЧИТАТЬ, но не менять.
2. **Если для задачи нужно изменить чужую папку или `shared/`** — не делай этого. Остановись и скажи пользователю: «Это зона <роль>, нужно согласовать с ним. Предлагаю такое изменение: …».
3. **Схема таблиц — только из `shared/DATA_CONTRACT.md`.** Не придумывай свои названия таблиц и полей. Если поля не хватает — предложи изменение контракта пользователю, а не меняй его молча.
4. **Никогда не коммить данные и секреты:** файлы `.xls`, `.rar`, `.csv`, `.db`, `.parquet`, папку `data/`, файлы `.env`, API-ключи. Ключи читать только из переменных окружения.
5. **Персональные данные пациентов (фамилия, имя) не отправлять во внешние API нейросетей.** В LLM передаются только обезличенные признаки (категории услуг, давность, сегмент, теги). Имя подставляется в текст уже после генерации.
6. **Не коммить в `main` напрямую.** Работай в ветке своей роли (см. `CONTRIBUTING.md`), в `main` — только через Pull Request.
7. **Не удаляй и не переписывай файлы, которые создал не ты в этой сессии**, без явного согласия пользователя.
8. **Не выдумывай цифры.** Любая цифра для презентации должна считаться кодом из данных или быть явно подписана как допущение.
9. Пиши комментарии, README и сообщения коммитов **на русском**. Имена переменных, таблиц и полей — на английском (как в контракте).

## 4. Технический стек (общий для всех)

- Python 3.11+. Зависимости каждой роли — в `<папка>/requirements.txt`.
- Чтение `.xls`: библиотека `xlrd` (формат старый, `openpyxl` его не читает).
- Распаковка архива `anonymized.rar` (формат RAR5): `bsdtar`, `unrar` или свежий 7-Zip. Старый `p7zip 16` не справляется.
- База: SQLite-файл `data/ilfa.db` для локальной работы; PostgreSQL в Docker для демо. Подключение через SQLAlchemy и переменную окружения `DATABASE_URL` (по умолчанию `sqlite:///data/ilfa.db`).
- API: FastAPI. Интерфейс: Streamlit.
- LLM: через API, ключ в `.env` (например, `LLM_API_KEY`). Предпочтительно российский провайдер (YandexGPT / GigaChat) из-за 152-ФЗ.

## 5. Факты о данных (проверено на полном архиве)

- 8 652 файла, период 01.10.2025–30.09.2026, 1 918 уникальных пациентов (ключ: Фамилия + Имя), 12 669 строк услуг, 425 уникальных услуг, 18 врачей, выручка ≈ 129,2 млн ₽.
- Структура файла (лист `Лист1`): строки шапки «ключ в колонке A — значение в колонке B»: `№`, `Дата визита` (дд.мм.гггг), `Склад` (всегда пусто), `Фамилия`, `Имя`, `Пол` (Жен/Муж/пусто), `Контрагент` (всегда пусто), `Автор` (администратор), `Комментарий`; затем строка `Товары и услуги`, строка заголовков `Наименование | Врач | Количество | Цена | Сумма` и строки услуг.
- 2 461 визит (28%) без единой услуги. 42% пациентов были только один раз.
- Пол пуст в 2 117 визитах, восстанавливается по другим визитам того же пациента (конфликтов нет), итого пол известен у 1 380 пациентов.
- В 24% строк `Сумма < Цена × Количество` (скидки), в 3% строк `Сумма = 0`.
- Комментарий заполнен в 86% визитов (свободный текст, полезные сигналы: «кормящая мама», «тревожная», «презентация имплантации»).
- **Телефона и даты рождения в данных НЕТ.** Возраст и «жизненную ситуацию» выводим косвенно (детские услуги, комментарии).
- Имена анонимизированы: «Фамилия 420», «Имя 420».

## 6. Как начинать работу (алгоритм для ИИ)

1. Спроси пользователя его роль, если он её не назвал.
2. Прочитай этот файл, `shared/DATA_CONTRACT.md`, `CONTRIBUTING.md` и `<папка роли>/AGENTS.md`.
3. Проверь, что ты в ветке роли (`git branch --show-current`). Если нет — предложи переключиться.
4. Посмотри, что уже сделано в папке роли и в `<папка>/STATUS.md`.
5. Предложи пользователю ближайший шаг из плана роли и выполняй план по шагам, после каждого шага обновляя `<папка>/STATUS.md`.
