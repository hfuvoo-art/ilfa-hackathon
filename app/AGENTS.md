# app/ — Fullstack-разработчик. План для ИИ-ассистента

Ты помогаешь **fullstack-разработчику**. Твоя зона — папка `app/`, а также корневые `docker-compose.yml`, `Dockerfile`, `Makefile`, `.env.example` (их создаёт и поддерживает fullstack). Перед работой прочитай корневой `AGENTS.md` и `shared/DATA_CONTRACT.md`.

## Цель
Собрать **работающий прототип**, который покажем жюри и который запускается из репозитория одной командой. Обязательный пункт сдачи — «ссылка на репозиторий с рабочим прототипом»; критерий жюри — «проработка архитектуры».

## Вход
- База по контракту (строит `etl/`), сегменты (`analytics/`), таблица `offers` (`offers/`).
- Пока их нет — работай на **заглушках**: `app/fixtures.py` генерирует 20–30 фейковых пациентов по схеме контракта.

## Выход
1. `app/api/` — FastAPI.
2. `app/ui/` — Streamlit (многостраничное приложение).
3. Корневые `Dockerfile`, `docker-compose.yml` (сервисы: `db` Postgres, `api`, `ui`), `Makefile`, `.env.example`.
4. `app/README.md` и раздел «Как запустить» в корневом README.
5. `app/ARCHITECTURE.md` — схема архитектуры (mermaid) для презентации.

## Экраны (минимум для демо)
1. **Кому позвонить сегодня** — список офферов по `priority`; фильтры: сегмент, триггер, врач; у строки: пациент, повод, тон, текст, кнопка «Скопировать»; отметка результата (`no_answer`, `booked`, `refused`, `call_back`, `sent`) → таблица `contacts`.
2. **Карточка пациента** — таймлайн визитов (дата, услуги, врач, сумма), сегмент, LTV, теги из комментариев, все офферы пациента, кнопка «Перегенерировать текст» (вызывает `offers`).
3. **Сегменты** — размеры и выручка сегментов, выгрузка списка сегмента в CSV.
4. **Аналитика** — графики из `analytics/charts/`.
5. **Загрузка данных** — загрузить новые `.xls` → сохранить в `data/inbox/` → вызвать загрузчик из `etl/` → показать, сколько добавлено.

## API
| Метод | Путь | Что делает |
|---|---|---|
| GET | `/health` | проверка |
| GET | `/stats` | общие метрики |
| GET | `/segments` | сводка сегментов |
| GET | `/patients?segment=&trigger=&q=&limit=` | список |
| GET | `/patients/{patient_id}` | карточка + визиты + услуги |
| GET | `/patients/{patient_id}/offers` | офферы пациента |
| POST | `/patients/{patient_id}/offers/regenerate` | перегенерация текста (через модуль `offers`) |
| GET | `/calls?segment=&trigger=&limit=` | список «кому позвонить» |
| POST | `/contacts` | отметить результат контакта |
| GET | `/contacts` | история контактов |
| POST | `/upload` | загрузка `.xls` → ETL |
| GET | `/analytics/{chart}` | данные графиков |
Интерфейс ходит в API по `API_URL` (по умолчанию `http://localhost:8000`), а не напрямую в базу.

## Шаги

### Шаг 1. Каркас (часы 0–4)
- Структура `app/api/main.py`, `app/ui/Home.py` + `app/ui/pages/`.
- `app/fixtures.py` с фейковыми данными по контракту; API отдаёт заглушки.
- `Dockerfile` + `docker-compose.yml` + `.env.example` (`DATABASE_URL`, `API_URL`, `LLM_API_KEY=`).
- `Makefile`: `make api`, `make ui`, `make load` (вызывает `python -m etl.load`), `make offers`.

### Шаг 2. Реальные данные (часы 4–14)
- Подключение через SQLAlchemy по `DATABASE_URL`.
- Список пациентов и карточка на реальной базе (как только `etl/` отдал черновик).
- Сегменты и офферы **читаются из таблиц**, а не пересчитываются в API.

### Шаг 3. Ключевые экраны (часы 14–26)
- «Кому позвонить сегодня» и карточка пациента полностью.
- Таблица `contacts` (создаёт app) и отметка результата.
- Загрузка `.xls` через интерфейс.

### Шаг 4. Аналитика и полировка (часы 24–32)
- Встроить графики аналитика, выгрузку сегмента в CSV.
- Простая защита: пароль из `.env` на вход в интерфейс (тема персональных данных).
- Русские подписи, название сервиса, аккуратная вёрстка.

### Шаг 5. Деплой и надёжность (часы 30–38)
- Стенд (Render / Railway / Yandex Cloud / VPS). **На публичный стенд — только анонимизированные данные**, доступ по паролю.
- Демо не должно зависеть от LLM: офферы предрассчитаны в базе.
- Корневой README: что это, скриншоты, `docker compose up`, команда и роли.

### Шаг 6. Архитектура (часы 32–40)
`app/ARCHITECTURE.md`, mermaid-схема:
Медицинская ИС (без API) → выгрузка xls (вручную / RPA) → `data/inbox` → ETL → PostgreSQL → аналитика и сегменты (ночной пересчёт) → движок офферов (правила + LLM в РФ-контуре) → FastAPI → веб-интерфейс администратора и маркетолога → (этап 2) SMS / мессенджеры / телефония.
Отметить: где хранятся персональные данные; что уходит в LLM (только обезличенные признаки); как масштабируется на всю сеть.

### Шаг 7. Код-фриз и демо (часы 40–48)
- После код-фриза — только исправление багов.
- Сценарий демо: открыть «Кому позвонить» → выбрать пациента → история и персональный текст → отметить звонок. Записать резервное видео.

## Зависимости
- От `etl/`: схема (сразу, контракт) и данные (~3 час).
- От `analytics/`: сегменты (~16 час), функции графиков.
- От `offers/`: таблица `offers` (~20 час), функция перегенерации.
- Отдаёшь `docs/`: скриншоты (~30 час), стенд и схему архитектуры (~36 час).

## Критерии готовности
- Чистый клон + данные в `data/raw` + `docker compose up` → всё работает по README.
- Демо-сценарий проходит без ошибок.
- В репозитории нет данных пациентов и ключей.

## Нельзя
- Менять `etl/`, `analytics/`, `offers/`, `docs/`, `shared/` — только импортировать их функции. Нужна правка — попросить владельца.
