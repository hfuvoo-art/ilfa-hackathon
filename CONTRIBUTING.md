# Как работаем вместе (правила для людей)

## Ветки

| Роль | Ветка | Папка |
|---|---|---|
| Data-инженер | `etl` | `etl/` |
| Аналитик | `analytics` | `analytics/` |
| ML/LLM-разработчик | `offers` | `offers/` |
| Fullstack | `app` | `app/` |
| Руководитель | `docs` | `docs/` |

- `main` — только рабочий, проверенный код. Напрямую в `main` не пушим.
- Каждый работает в своей ветке и меняет файлы только в своей папке.
- Сделал законченный кусок (например, «парсер работает») → открыл Pull Request в `main` → кто-то из команды глянул → Merge.
- Перед началом работы и перед PR подтягивай свежий `main`:
  ```bash
  git checkout <твоя-ветка>
  git pull origin main
  ```

## Первый запуск (один раз)

```bash
git clone https://github.com/hfuvoo-art/ilfa-hackathon.git
cd ilfa-hackathon
git checkout -b <твоя-ветка>        # например: git checkout -b etl
git push -u origin <твоя-ветка>
```
Архив с данными положи в `data/raw/` и распакуй там же (см. `data/README.md`). В git он не попадёт.

## Коммиты

- Часто и маленькими кусками.
- Сообщение по-русски, с префиксом роли: `etl: парсер шапки визита`, `analytics: RFM-сегменты`, `offers: шаблоны текстов`, `app: экран карточки пациента`, `docs: модель экономики`.

## Чужие папки и общий контракт

- Чужую папку только читаем. Нужна правка — пишем владельцу в чат.
- `shared/DATA_CONTRACT.md` меняем только после согласования в общем чате. Изменение контракта — отдельный PR с пометкой `shared:` и предупреждением всем.

## Нельзя коммитить

- Данные: `.xls`, `.rar`, `.csv`, `.db`, `.parquet`, папку `data/`.
- Ключи и пароли: `.env`, токены нейросетей. Для примера — `.env.example` без настоящих значений.
- Если случайно закоммитил ключ — сразу скажи в чат, ключ нужно перевыпустить.

## Конфликты

1. Не паникуем и не делаем `git push --force` в `main`.
2. `git pull origin main` в своей ветке, решаем конфликт, коммитим.
3. Если конфликт в чужой папке — значит, кто-то нарушил правило «только своя папка». Зовём владельца папки.

## Статус

В каждой папке есть `STATUS.md`: что сделано, что в работе, что блокирует. Обновляй его после каждого шага — это видят все, включая руководителя, и нейросети других участников.

## Синки

Короткий созвон или сообщение в чат каждые 4–6 часов: что сделал, что дальше, что мешает. Отдельно сообщай, когда отдаёшь результат другим («таблица `patients` готова, лежит в `data/ilfa.db`»).
