# etl/ — Data-инженер. План для ИИ-ассистента

Ты помогаешь **data-инженеру**. Твоя зона — только папка `etl/`. Перед работой прочитай корневой `AGENTS.md` и `shared/DATA_CONTRACT.md`.

## Цель
Превратить 8 652 файла `.xls` в чистую базу по контракту (`visits`, `visit_items`, `services`, `patients`). От этой базы зависят все остальные роли, поэтому **скорость важнее идеальности**: сначала черновой результат, потом чистка.

## Вход
- `data/raw/anonymized/*.xls` (структура файла описана в корневом `AGENTS.md`, раздел 5).

## Выход (что должно появиться в `etl/`)
1. `etl/parse.py` — функция `parse_file(path) -> (visit: dict, items: list[dict])`.
2. `etl/categories.py` — функция `categorize(service_name) -> str` и словарь `FOLLOW_UP_DAYS`.
3. `etl/ids.py` — функция `make_patient_id(last_name, first_name) -> str` (sha1, 12 символов, см. контракт). Другие роли будут её импортировать.
4. `etl/load.py` — точка входа: `python -m etl.load data/raw/anonymized` строит/обновляет базу по `DATABASE_URL`.
5. `etl/requirements.txt` (xlrd, pandas, sqlalchemy).
6. `etl/README.md` — как запустить, сколько длится, что получается.
7. `etl/DATA_QUALITY.md` — найденные проблемы данных и как решены (с количествами).

## Шаги

### Шаг 1. Черновой парсер (цель: 2–3 часа от старта)
- Читать через `xlrd.open_workbook(path).sheet_by_index(0)`.
- Шапку разбирать **по названию ключа в колонке A** (не по номеру строки): `№`, `Дата визита`, `Фамилия`, `Имя`, `Пол`, `Автор`, `Комментарий`.
- Таблица услуг начинается со строки, где колонка A = `Наименование`. Читать до конца листа, пропуская пустые строки.
- `№` приходит как float (`112337.0`) → привести к int. Дата — строка `дд.мм.гггг`.
- Сразу сохранить `visits` и `visit_items` в базу и **выгрузить черновой CSV** для команды (передать в чат, не в git). Записать в `STATUS.md`: «черновые данные готовы».
- Проверка: 8 652 визита, 12 669 строк услуг, сумма `sum` ≈ 129 217 717 ₽.

### Шаг 2. Очистка (до ~10 часа)
- Нормализовать пробелы во всех текстовых полях (`" ".join(s.split())`).
- Врач: привести к виду «Фамилия Имя Отчество» (`.title()`); в данных есть ФИО капсом.
- Пол: `Жен`→`F`, `Муж`→`M`. Пустой пол заполнить по другим визитам того же пациента (конфликтов в данных нет). Остаток — `unknown`.
- `discount = max(price*qty - sum, 0)`.
- `has_services = len(items) > 0`; `total_sum = sum(items.sum)`.
- Проверить дубли `visit_id` и дубли файлов. Записать всё в `DATA_QUALITY.md` с цифрами.
- **Не удалять** визиты без услуг (их 28%): это консультации/неявки, они важны для аналитики.

### Шаг 3. Справочник услуг `services` (до ~14 часа, согласовать с аналитиком)
- 425 уникальных названий → категории из контракта. Правила по ключевым словам, порядок важен (первое совпадение):
  - `Детская`: `молочн|детск`
  - `Ортодонтия`: `миниимплант|брекет|элайнер|ортодонт|аппарат|хааса|ретейнер|каппа|трейнер|пластинк`
  - `Имплантация`: `имплант|абатмент|формировател|синус|костн`
  - `Гигиена`: `гигиен|air ?flow|фторир|отбеливан`
  - `Ортопедия`: `коронк|вкладк|накладк|винир|протез|e\.?max|циркон|сплинт`
  - `Хирургия`: `удален|резекц|цистэктом|разрез`
  - `Терапия`: `кариес|пломб|канал|пульп|периодонт|реставрац|эндодонт`
  - `Диагностика`: `томограф|\bкт\b|снимок|рентген|диагност|сканирован`
  - `Консультация`: `консультац|осмотр|при[её]м`
  - иначе `Прочее`
- Вывести список `Прочее` с количеством и выручкой, показать пользователю для ручной доразметки (цель: < 5% выручки в `Прочее`).
- Заполнить `follow_up_days` (Гигиена 180, Имплантация 365, Ортодонтия 45, Детская 180, Терапия 365, Ортопедия 365) и `is_chain_start` (установка импланта, брекет-система, элайнеры, КТ, лечение каналов).
- Колонку `visit_items.category` заполнить из справочника.

### Шаг 4. Витрина `patients` (до ~16 часа)
Все базовые поля из контракта (`first_visit`, `last_visit`, `n_visits`, `n_paid_visits`, `revenue`, `avg_check`, `days_since_last`, `categories`, `main_doctor`, `is_child`). Поля `segment`, `rfm`, `ltv_*` создать пустыми — их заполняет аналитик.
Дата отчёта для `days_since_last` = максимальная дата визита в данных (30.09.2026), параметризовать.

### Шаг 5. Инкрементальная загрузка (до ~24 часа)
- `python -m etl.load <папка>` загружает только новые `visit_id`, затем пересчитывает `services` и `patients`.
- Повторный запуск не создаёт дублей.
- Лог: сколько файлов прочитано, новых, с ошибками.
- Это аргумент для жюри: «у клиники нет API, но процесс обновления работает: выгрузил xls в папку → нажал кнопку».

### Шаг 6. Документация (до ~36 часа)
- `etl/README.md`, `DATA_QUALITY.md`.
- Схема базы в mermaid (`erDiagram`) в README — для слайда архитектуры.
- Одна фраза для презентации: «8 652 разрозненных файла → единая база за N секунд».

## Критерии готовности
- `python -m etl.load data/raw/anonymized` на чистой машине строит базу без ошибок.
- Сверка: 8 652 визита, 12 669 строк услуг, 1 918 пациентов, выручка ≈ 129,2 млн ₽.
- У каждой услуги есть категория; повторный запуск не дублирует данные.

## Нельзя
- Менять файлы вне `etl/`. Менять контракт без согласования.
- Коммитить `.xls`, `.csv`, `.db`.
