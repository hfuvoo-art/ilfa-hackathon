# Передача аналитики команде «Ильфа»

## Что готово

Финальные краткие выводы для защиты — в `TEAM_SUMMARY.md`, воспроизводимые команды — в `README.md`, результаты проверок — в `VALIDATION.md`.

- **app/**: функция `analytics.charts.build_charts(engine)` возвращает восемь графиков Plotly; `analytics.segments.compute_segments(engine)` заполняет `patients.segment`, `rfm`, `ltv_hist`, `ltv_pred` (имеет побочный эффект — запись в БД).
- **offers/**: `python -m analytics.services --transitions-csv` — агрегированные переходы между категориями. Учитываются только соседние визиты с определённой основной категорией; визиты без подходящей категории разрывают цепочки, а бесплатный визит с услугой может участвовать.
- **docs/**: в `FINDINGS.md` — агрегаты из предыдущего отчёта и явно обозначенный сценарий кампании. Данные следует сверить с локальной итоговой базой перед защитой.

## Вопросы на согласование до использования в клинике

1. Подтвердить словарь начала/продолжения лечения с ETL и медицинским специалистом. Сегмент «Незавершённое лечение» сейчас эвристический, не является подтверждением диагноза или плана лечения.
2. Согласовать порядок приоритетов бизнес-сегментов с командами `offers/` и `app/`. В реализации «Ценные лояльные» и «Новые» проверяются до «Незавершённое лечение»; последний имеет приоритет над «Спящие» и «Пропал после 1 визита».
3. Проверить сценарный экономический эффект на пилотной кампании с контрольной группой; учесть затраты, скидки и согласие пациентов на коммуникации.
4. Для аналитического демо допустимо сохранить анестезию, седацию, расходники и оплаты без однозначной привязки в «Прочее» (по отчёту ETL — 4,53% выручки). Это рабочая позиция аналитики; согласование offers отдельно. Не трактовать такую категорию как самостоятельное показание или повод для предложения.

## Интеграция с app: обновление 27.11.2026

Актуальный `app/README.md` и Docker Compose используют **SQLite и локально, и в Docker**. PostgreSQL не является блокером этого демо. Упоминание PostgreSQL в общем контракте устарело относительно конфигурации приложения; чужие файлы этим PR не изменяются.

PR аналитики: https://github.com/hfuvoo-art/ilfa-hackathon/pull/7 . Наличие кода в ветке или его объединение **не заполняет автоматически базу на компьютере Роберта**. После ревью и объединения PR, в копии с актуальным `main`, `.env` и архивом в `data/raw/anonymized/`:

```bash
docker compose build
docker compose run --rm etl
docker compose run --rm api python -m analytics.segments
docker compose run --rm api python -m analytics.services --transitions-csv
docker compose up --build
```

Сервис `api` использует тот же образ и том `./data:/app/data`, поэтому команда сегментации записывает четыре поля именно в `data/ilfa.db`, которую читает приложение. Образ нужно пересобрать после получения кода аналитики. Команды соответствуют текущему Compose/Dockerfile; Docker в среде этой проверки не запускался. Перед изменением существующей базы нужна локальная резервная копия.

Без Docker, из корня с установленным Python и уже собранной базой:

```powershell
python -m pip install -r analytics/requirements.txt
$env:DATABASE_URL = "sqlite:///data/ilfa.db"
python -m analytics.segments
python -m analytics.services --transitions-csv
```

Успешная сегментация проверяет заполнение всех четырёх полей и сверки внутри транзакции, затем печатает число пациентов и суммы по сегментам. На неизменённом полном архиве ожидаются 1 918 пациентов и общая выручка 129 217 716,86 ₽. Это критерий проверки у владельца базы, **не утверждение, что его база уже изменена**. После новых загрузок ETL сегментацию нужно повторить, затем обновить offers. Матрица переходов печатается в stdout; её можно передать offers локально без добавления выгрузок в Git.

Экран сегментов зависит от заполненных полей. Экран «Кому позвонить» дополнительно требует `offers` и `comment_tags` от владельца offers; одной сегментации недостаточно. Пароль задаёт владелец стенда через `APP_PASSWORD` в локальной `.env`, в Git он не передаётся.

Для руководителя: соответствие четырёх групп Excel, источники чеков, пороги 90/180 и предлагаемые правила дедупликации добавлены в `FINDINGS.md`. Годовой шаблон экономики нельзя автоматически заполнить цифрами отдельного 90-дневного сценария. Финальные размеры групп и чеки требуют актуальной базы и согласованных поводов offers.

## Безопасный запуск и проверка

В корне репозитория после установки зависимостей:

```powershell
python -m unittest discover -s analytics -p "test_*.py" -v
```

Для запуска на реальной базе локально нужны согласованный `DATABASE_URL` и резервная копия базы **до** выполнения записывающей команды `python -m analytics.segments`. Не публикуйте `data/`, `.venv/`, SQLite, Excel, CSV с данными, `charts/real_aggregates.json` и HTML, сформированный из неутверждённых агрегатов.

## Изменения финального аудита

- Исторический LTV сохраняет отрицательную чистую выручку по контракту; ограничение снизу применяется только к прогнозному среднему чеку.
- Перед записью проверяются выручка и числа визитов каждого пациента, а также отсутствие визитов без записи в витрине пациентов. Ошибки прерывают транзакцию. Базовые поля ETL не изменяются.
- Ноутбук включает разведку, сегменты, LTV, услуги, переходы, восемь графиков и сценарий кампании; сохранён без результатов выполнения.
- `app/`, `offers/`, `docs/`, `etl/` не изменялись. Материалы для их владельцев передаются через этот PR; интеграция графиков в интерфейс остаётся за владельцем `app/`.
