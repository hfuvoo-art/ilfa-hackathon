# analytics/ — Аналитик. План для ИИ-ассистента

Ты помогаешь **аналитику данных**. Твоя зона — только папка `analytics/`. Перед работой прочитай корневой `AGENTS.md` и `shared/DATA_CONTRACT.md`.

## Цель
Показать, как устроена экономика клиники: кто приносит деньги, кто уходит, какие услуги прибыльны, когда пики и провалы. Сегменты, которые ты строишь, используют ML (`offers/`) и интерфейс (`app/`), а цифры — руководитель (`docs/`). Главный критерий жюри «глубина и наглядность аналитики» — твой.

## Вход
- База по контракту (строит `etl/`). Пока её нет — черновой CSV от data-инженера или сэмпл из 200 файлов, разобранный временным скриптом в твоей папке.

## Выход (в `analytics/`)
1. `analytics/analysis.ipynb` — воспроизводимый ноутбук: разведка, сегменты, LTV, услуги, сезонность.
2. `analytics/segments.py` — функция `compute_segments(engine)`, которая заполняет `patients.segment`, `patients.rfm`, `patients.ltv_hist`, `patients.ltv_pred`. Запуск: `python -m analytics.segments`.
3. `analytics/charts/` — функции, возвращающие графики (plotly), чтобы fullstack встроил их в интерфейс.
4. `analytics/FINDINGS.md` — ключевые выводы и цифры для презентации (таблицы + одна строка вывода к каждому графику).
5. `analytics/requirements.txt`.

## Шаги

### Шаг 1. Разведка (часы 2–6)
- Базовые метрики: визиты, пациенты, выручка, средний чек, визитов на пациента. Сверка: 8 652 / 1 918 / ≈129,2 млн ₽.
- Распределение выручки по пациентам, проверка Парето (какая доля пациентов даёт 80% выручки).
- Визиты без услуг (28%): что пишут в комментариях, как распределены по времени.

### Шаг 2. Категории услуг (часы 6–14, вместе с etl)
Проверить разметку категорий от data-инженера, предложить исправления для `Прочее`. Изменения передать ему (сам `etl/` не меняй).

### Шаг 3. Сегментация (часы 8–16)
**A. RFM** — квантили 1–3 по Recency (`days_since_last`), Frequency (`n_paid_visits`), Monetary (`revenue`). Код вида `R3F2M3` в `patients.rfm`.

**B. Бизнес-сегменты** (значение `patients.segment`, ровно эти строки — их используют другие роли):
| segment | Правило (стартовое, можно уточнять) |
|---|---|
| `Ценные лояльные` | revenue в топ-20%, n_paid_visits ≥ 3, days_since_last ≤ 180 |
| `Новые` | first_visit за последние 60 дней |
| `Пропал после 1 визита` | n_visits = 1, days_since_last > 90 |
| `Незавершённое лечение` | есть услуга с `is_chain_start` без продолжения (установка импланта без коронки на имплант; брекеты без коррекции > 60 дней; КТ/консультация имплантации без установки) |
| `Только гигиена` | все платные услуги в категории `Гигиена` |
| `Спящие` | n_paid_visits ≥ 2, days_since_last > 180 |
| `Дети и семьи` | is_child = true |
| `Активные` | все остальные |
Приоритет при пересечении — сверху вниз (кроме `Незавершённое лечение`: его ставить выше `Спящие` и `Пропал`). Для каждого сегмента: размер, выручка, средний чек, рекомендация, что предложить (передать в `offers/`).
Учти: у пациентов, впервые пришедших в августе–сентябре 2026, просто не было времени вернуться — не путать их с «пропавшими».

### Шаг 4. LTV (часы 12–20)
- `ltv_hist` = revenue.
- `ltv_pred` на 12 месяцев: средний чек × ожидаемое число визитов в год (по когортам месяца первого визита). Если успеваешь — BG/NBD + Gamma-Gamma (`lifetimes`/`pymc-marketing`).
- LTV по сегментам и по **первой услуге** пациента (какая «входная» услуга приводит самых ценных).
- Явно указать ограничение: данных 12 месяцев.

### Шаг 5. Услуги, скидки, врачи (часы 14–22)
- Топ услуг и категорий по выручке, количеству, среднему чеку.
- Скидки: сколько ₽ уходит в скидки (`discount`), по каким услугам.
- Матрица переходов «категория визита N → категория визита N+1» — **отдать в `offers/`** (это основа триггеров и next-best-service). Сохранить как таблицу или CSV в `data/`.
- Нагрузка по врачам — только для внутреннего анализа, без «рейтинга врачей» на слайдах.

### Шаг 6. Сезонность (часы 18–24)
- Визиты и выручка по месяцам, дням недели; по категориям.
- Предварительно: минимум октябрь 2025, пик май 2026.
- Вывод: в какие месяцы запускать кампании, чтобы заполнить провалы.

### Шаг 7. Дашборд и выводы (часы 22–36)
- Графики: структура сегментов, Парето, LTV по сегментам, топ услуг, сезонность, когорты удержания, переходы между категориями.
- Под каждым графиком — одна строка «что это значит для клиники».
- В `FINDINGS.md` таблица для руководителя: сегмент → размер → средний чек → потенциал возврата.

## Зависимости
- Ждёшь данные от `etl/` (черновые ~3 час).
- Отдаёшь `offers/` сегменты и матрицу переходов к ~16 часу.
- Отдаёшь `docs/` черновые цифры к ~10 часу, финальные к ~24.
- Отдаёшь `app/` функции графиков и `compute_segments`.

## Критерии готовности
- `python -m analytics.segments` заполняет поля в `patients` воспроизводимо.
- Сумма по сегментам сходится с общими цифрами.
- На каждом графике есть вывод.

## Нельзя
- Менять файлы вне `analytics/`. Выдумывать цифры. Коммитить данные и выгрузки.
