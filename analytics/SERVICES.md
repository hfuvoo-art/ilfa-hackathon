# Услуги, скидки и переходы

## Запуск

Команды запускаются из корня проекта с установленными зависимостями из `analytics/requirements.txt`.

```powershell
python -m analytics.services
python -m analytics.services --transitions-csv
python -m unittest analytics.test_services -v
```

Первая команда печатает отчёт в JSON. Вторая печатает только агрегированную таблицу переходов в CSV. Обе используют `DATABASE_URL` или локальную SQLite по умолчанию. Отчёт читает таблицы, а LTV берёт из `patients.ltv_hist`, который заполняется командой `python -m analytics.segments`. Из Python доступна функция `build_service_report(engine)`.

## Как читать отчёт

- Выручка категории — сумма `visit_items.sum` по её строкам. Строки с отрицательной суммой уменьшают выручку. Доля категории считается от общей выручки по строкам услуг. При нулевой общей выручке поле доли пустое. Средний чек категории показывает выручку этой категории в среднем на визит, где она встретилась.
- Количество услуг считается по положительному `qty` у строк без признаков корректировки. Пропуски количества вынесены в отдельный счётчик. Показатель количества и число строк могут отличаться, если за одну строку оказано несколько единиц услуги.
- Скидка берётся из `discount` у строк с положительным количеством и известными неотрицательными ценой и суммой. Сумма ноль при положительной цене может давать полную скидку по формуле контракта. Строки с отрицательным количеством, ценой или суммой учитываются отдельно как возможные возвраты или корректировки. В контракте отсутствует тип операции, поэтому различить их причины по одному знаку нельзя.
- Сверка показывает выручку по строкам услуг, категориям и визитам. Отдельно выводятся расхождения по отдельным визитам, строки услуг без визита и пропуски сумм.
- Для разреза LTV смотрим на первую записанную услугу по дате и номеру визита. При нескольких услугах в одном визите берём первое название по алфавиту, поскольку фактический порядок в контракте отсутствует. Возможные корректировки и нулевое количество исключаются. Если есть подходящая услуга без даты, первый вход считается неизвестным; это правило применяется и в `summarize_ltv`. Каждый пациент попадает в одну строку отчёта. При неизвестной первой категории используется отдельная группа, а средний LTV считается только по известным значениям.

## Таблица для offers/

В каждом визите выбирается одна категория по наибольшей сумме строк без признаков корректировки. При равенстве приоритет у известной категории, затем действует порядок по алфавиту. Бесплатный визит с услугой может участвовать. Пары строятся между соседними визитами пациента, отсортированными по дате и номеру. Визит без подходящей категории разрывает последовательность. История с визитом без даты исключается из переходов, поскольку его место неизвестно.

| Поле | Значение |
|---|---|
| `from_category` | Основная категория предыдущего визита |
| `to_category` | Основная категория соседнего следующего визита, в том числе той же категории |
| `n_transitions` | Число таких пар визитов |
| `n_patients` | Число уникальных пациентов с такой парой |
| `transition_share` | Доля этой пары среди учтённых исходящих переходов из `from_category`, от 0 до 1 |

CSV содержит только агрегаты. Доля показывает, куда переходили пациенты в наблюдаемых соседних визитах с известными категориями. Она не оценивает вероятность возвращения всех пациентов.

В синтетическом ноутбуке получился один переход.

| `from_category` | `to_category` | `n_transitions` | `n_patients` | `transition_share` |
|---|---|---:|---:|---:|
| Гигиена | Гигиена | 1 | 1 | 1,0 |

## Вопросы по категории «Прочее» для Data-инженера

Отчёт `other` выводит итог категории и её позиции по названиям, выручке и количеству. Пустая или неизвестная категория выводится отдельно. На синтетическом наборе с корректировками «Прочее» содержит 75 ₽ чистой выручки, около 16,9% от 445 ₽. В исходной синтетике ноутбука категория отсутствует.

1. Какие строки «Прочее» являются самостоятельными услугами, а какие относятся к материалам, пакетам, доплатам или техническим операциям?
2. Какие названия являются синонимами уже размеченных услуг и требуют общего правила нормализации? В каком порядке применять правила, когда название подходит к нескольким категориям?
3. Какие строки с пустой категорией возникли из-за отсутствия услуги в справочнике и как проверять соответствие `visit_items.category` и `services.category` после обновления?
4. Как источник обозначает возвраты, сторно и нулевые суммы, в том числе полную скидку и бесплатную услугу? От ответа зависит раздельная оценка скидок и корректировок.
